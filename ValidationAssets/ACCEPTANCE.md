# 300 万点场景验收

## 固定输入

验收使用 `drjohnson_full_sh3.ply`，必须同时满足：

- 3,177,554 个高斯，完整文件，不裁点；
- SH degree 3，包含连续的 45 个 `f_rest_*` 属性；
- 文件大小 788,034,924 字节；
- SHA-256：`92f4898839ec4ad7f197cf6c74b89918b35ea712b4e41435593ccb152d22b7f5`。

执行以下命令可下载或重新验证本地文件：

```bash
./Scripts/download_validation_scene.sh
```

## 实体机步骤

1. 使用 Release 配置将 App 安装到一台 iOS 18 或更高版本的实体 iPhone。
2. 将 `drjohnson_full_sh3.ply` 传入该 iPhone 的“文件”App；不要把它加入 Xcode 的 Copy Bundle Resources。
3. 从手机主屏幕启动 App，确认内置 `sample_scene.ply` 可以正常显示。
4. 点右上角文件按钮，选择 `drjohnson_full_sh3.ply`。
5. 等待状态卡进入就绪态，然后连续执行环绕、缩放、重置视角和前后台切换。
6. 不连接 Xcode 调试器连续运行至少 10 分钟，记录状态卡与系统性能数据。

## 必须通过

- 状态卡显示 `3,177,554` 个高斯、`SH3`、`49 chunks`，没有裁点或降为 SH0。
- 首帧与多个观察角度下没有黑屏、持续闪烁、明显色偏、NaN 拉伸或大片高斯消失。
- 加载、10 分钟观察、相机操作和前后台切换期间没有崩溃或系统内存终止。
- 加载结束后 UI 操作能够持续响应，候选预算变化不会造成长时间画面冻结。
- 状态卡持续产生已完成帧 FPS、候选数、GPU 时间和排序时间，而不是一直停留在加载态。

场景总点数与每帧候选数是两个不同指标。验收要求完整加载全部 3,177,554 个高斯及其属性；渲染器可以根据性能从完整场景中选择有界候选集，所以“绘制”数不要求等于场景总点数。

## 提交时附带的数据

每次声明通过时，应记录：iPhone 型号、iOS 版本、屏幕方向和分辨率、Release 构建提交号、加载耗时、稳定后的 FPS 范围、平均 GPU 毫秒、候选数范围、最近排序毫秒，以及 10 分钟内是否发生热降频或内存终止。没有指定参考 iPhone 型号前，不设置跨设备统一的 FPS 数字门槛。
